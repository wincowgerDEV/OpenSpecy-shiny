# Static webR Analysis Path

This repository now has a side-by-side static analysis path at `site/analysis/`.
The existing Shinylive app remains available and is still built by
`tools/build-shinylive.R`.

## Why webR is lazy-loaded

Normal static pages should behave like ordinary website pages: HTML, CSS, and
small JavaScript only. The analysis page imports local page modules on load, but
does not import `webr.mjs`, start R, mount packages, or download reference
libraries until the user clicks `Analyze`.

At analysis time, `src/analysis/webrEngine.js`:

1. Dynamically imports webR from the generated Shinylive assets.
2. Starts a single webR instance and reuses it for later calls.
3. Mounts static webR package assets generated by Shinylive.
4. Sources `inst/webr/openspecy_engine.R`.
5. Downloads only the selected browser reference library.
6. Writes the selected user file into the webR virtual filesystem.
7. Calls one coarse R function: `openspecy_analyze_file(path, options)`.

## Browser reference libraries

The static webR deployment only supports:

- `medoid`
- `model`

The full Open Specy reference library is not bundled, mounted, downloaded, or
offered by the browser UI. The R wrapper enforces this through
`openspecy_available_libraries()` and `openspecy_validate_browser_library()`.
The JavaScript engine applies the same allowlist before fetching assets.

Supported assets are:

- `public/data/openspecy-medoid.rds`
- `public/data/openspecy-model.rds`

`tools/build-static-webr-site.R` can generate these with `--export-libs`. It
only exports the medoid/model variants used by the current Shiny app and
refuses unsupported library names. Asset size is checked before copying into
`site/data/`.

## File handling

The static page does not use Shiny `fileInput()`.

1. The browser receives the selected `File`.
2. JavaScript reads it once as an `ArrayBuffer`.
3. The bytes are written to `/uploads/<safe-name>` in webR's virtual filesystem.
4. Options are written once as JSON to `/uploads/options-*.json`.
5. R receives only file paths and reads the file from the virtual filesystem.

This keeps the R/JavaScript boundary coarse-grained and leaves room for future
WORKERFS mounting or binary readers.

CSV, TSV, and TXT are exposed first in the UI. The R wrapper calls
`OpenSpecy::read_any()`, so additional formats can be enabled once they are
validated in browser webR.

## Difference from Shiny/Shinylive

Shiny/Shinylive still owns the existing full application interface. It uses
reactive values, inputs, outputs, observers, and Shiny-specific upload paths.

The static webR path keeps those concerns out of R:

- JavaScript owns UI state, file selection, progress messages, and tables.
- R owns Open Specy computation.
- Browser R functions are pure, Shiny-free wrappers in `inst/webr/`.
- Results are JSON-friendly lists and data frames.

This lets the static site evolve without removing the Shiny app immediately.

## R package dependencies

The browser wrapper directly requires `OpenSpecy` and `jsonlite`. The bundled
OpenSpecy 1.4.0 package imports `methods`, `data.table`, `jsonlite`, `yaml`,
`caTools`, `hyperSpec`, `mmand`, `plotly`, `digest`, `signal`, `glmnet`, `jpeg`,
and `shiny`.

The first static implementation mounts the generated Shinylive webR package
assets so these packages are static files served by GitHub Pages. A future
optimization should build a smaller webR package filesystem image containing
only the package closure required for the medoid/model workflow.

## Future formats and libraries

To add another small browser library:

1. Confirm it is small enough for GitHub and browser startup.
2. Add the exact library id to `browser_library_specs` in
   `tools/build-static-webr-site.R`.
3. Add a static asset mapping in `inst/webr/openspecy_engine.R`.
4. Add the UI option in `src/analysis/page.js`.
5. Keep the full reference library unsupported unless a separate storage plan is
   chosen.

To add binary formats:

1. Keep JavaScript writing or mounting the file once.
2. Add an R reader branch inside `openspecy_read_browser_file()`.
3. Return the same JSON-friendly match result shape.
4. Add manual validation with a small fixture file.

## Build flow

Current Pages build order:

```sh
Rscript tools/build-shinylive.R
Rscript tools/build-static-webr-site.R --export-libs
```

The second step adds `site/analysis/`, `site/r/`, `site/assets/logo.png`, and
only the medoid/model files under `site/data/`. It does not call `run_app()`,
does not depend on user-uploaded files, and does not alter the generated
Shinylive app.
